1. EXECUTIVE SUMMARY & VALUE PROPOSITION
================================================================================

LangGraph-Observe is an enterprise-grade, lightweight, and completely decoupled
observability platform engineered specifically for stateful AI agents and
cyclical workflows built on LangGraph and FastAPI.

Modern AI applications have evolved beyond simple linear prompt-response chains
into multi-agent, cyclic, and asynchronous graph networks. While general-purpose
application performance monitoring (APM) tools like Datadog and New Relic treat
LLM operations as opaque external HTTP requests, and proprietary vendors like
LangSmith introduce heavy cloud dependencies and steep recurring fees,
LangGraph-Observe delivers a high-performance, self-hosted alternative with:

  * Zero runtime latency impact via non-blocking, fail-open asynchronous queues.
  * Concurrency-safe, deterministic execution tree tracing across parallel fan-outs.
  * Real-time state delta diffing before and after each node execution.
  * Heuristic detection of infinite agent loops and runaway tool cycles.
  * Comprehensive token economics and live cost estimation across 5 major AI providers.
  * Strict client-side PII scrubbing and credential redaction prior to network egress.
  * A single-binary Windows executable (.exe) with zero external runtime requirements.

2. THE PROBLEM STATEMENT & INDUSTRY CONTEXT
================================================================================

Stateful agentic architectures introduce critical failure modes that standard
software monitoring cannot diagnose:

1. Silent State Corruption & Drift:
   In LangGraph, state is passed and mutated across multiple graph nodes. An
   errant node mutating an unexpected dictionary key or overwriting previous
   context silently compromises downstream agents without throwing a fatal code error.

2. Infinite Tool Loops & Runaway Cost:
   Ambiguous tool outputs or model hallucination frequently cause agents to enter
   cyclical invocation loops (calling the same search or query tool dozens of times),
   consuming hundreds of dollars in API credits within minutes.

3. Corrupted Traces Under Concurrency:
   Traditional APMs utilize thread-local or Last-In-First-Out (LIFO) call stacks.
   When LangGraph workflows execute parallel async branches (e.g., asyncio.gather),
   stack-based tracers cross-contaminate spans, creating invalid or corrupted trees.

4. Data Privacy Violations & Compliance Risks:
   AI agent prompts and tool arguments often contain credentials, session tokens,
   and customer Personally Identifiable Information (PII). Transmitting raw telemetry
   to external cloud monitors violates SOC2, HIPAA, and GDPR regulations.

5. Heavy Operational Overhead:
   Existing open-source monitoring solutions require orchestrating complex
   multi-container Docker environments (ClickHouse, Redis, vector DBs), making local
   debugging and rapid air-gapped deployment difficult.

LangGraph-Observe solves all of these challenges in a unified, lightweight package.

4. CORE SUBSYSTEMS & TECHNICAL DEEP DIVES
================================================================================

--------------------------------------------------------------------------------
A. Concurrency-Safe Tree Tracing (LangGraphTraceCallbackHandler)
--------------------------------------------------------------------------------
Problem:
LangGraph workflows support dynamic asynchronous fan-outs where multiple nodes
or tool executions run concurrently via asyncio.gather or parallel branches.
Traditional APMs use a LIFO stack to track active spans, which crashes or
misattributes parent-child relationships when tasks interleave.

Solution:
Authored a custom LangChain BaseCallbackHandler that deterministically tracks
the tree structure using LangChain's unique run_id and parent_run_id UUIDs.
By maintaining an internal, thread-safe mapping guarded by re-entrant locks
alongside Python's task-local ContextVar mechanism, the tracer guarantees that
every child span (LLM call, tool execution, or nested chain) is linked
unambiguously to its exact parent node regardless of execution concurrency.

--------------------------------------------------------------------------------
B. Microsecond State Delta Engine (calculate_state_diff & Safe Serializer)
--------------------------------------------------------------------------------
Problem:
Logging entire state snapshots on every graph step consumes massive database
storage and forces developers to manually scan large JSON blobs to determine
what actually changed.

Solution:
Constructed a recursive serialization engine that safely navigates circular
references, LangChain BaseMessage objects, Pydantic models (v1 and v2), and
dataclasses. The diff engine compares the state dictionary before and after
each node execution, tagging mutations with explicit semantic operations:
  * "added": New key introduced by the node.
  * "modified": Value updated from an old state to a new state.
  * "appended": Specifically optimized for chat message arrays. Detects list
    growth and records only newly appended messages and counts rather than
    duplicating the entire historical context.

--------------------------------------------------------------------------------
C. Automated Agent Loop & Anomaly Detection
--------------------------------------------------------------------------------
Problem:
Unclear prompt guidelines or tool failures can trap an LLM in an infinite loop,
re-invoking the same tool endlessly and draining inference budgets.

Solution:
Embedded an automated heuristic auditor inside Trace.compute_metrics():
  * Monitors all TOOL spans recorded in the trace.
  * Detects if any single tool is invoked 5 or more times total, OR 3 or more
    times with identical input argument payloads.
  * Automatically flags the trace with `has_tool_loop = True`, records the
    offending tool name, and displays an amber warning badge on the live dashboard.

--------------------------------------------------------------------------------
D. Client-Side PII & Secret Redaction Engine (PIIMasker)
--------------------------------------------------------------------------------
Problem:
Transmitting LLM prompts and agent states to observability backends often
exposes customer PII, Bearer tokens, and sensitive API keys.

Solution:
Engineered an in-memory client-side scrubber that executes prior to network
serialization:
  * Pre-compiled high-performance regular expressions for:
    - Email addresses
    - Credit card numbers (16-digit patterns)
    - US Social Security Numbers (SSNs)
    - API keys and tokens (e.g., sk-*, Bearer ey*)
    - International and domestic phone numbers
  * Case-insensitive dictionary key scrubbing for sensitive identifiers
    (password, token, access_token, api_key, cookie, secret, ssn, private_key).
  * Safe recursive traversal with depth limiting to prevent stack overflows.

--------------------------------------------------------------------------------
E. Multi-Vendor Token Economics & Real-Time Cost Engine
--------------------------------------------------------------------------------
Problem:
Modern multi-agent systems leverage heterogeneous models (e.g., GPT-4o for
planning, Claude 3.5 Haiku for guardrails, Gemini Flash for summaries).
Understanding consolidated operational cost requires normalized token accounting.

Solution:
Implemented a comprehensive token accounting matrix (`pricing.py`) supporting:
  * OpenAI: GPT-4o, GPT-4o-mini, o1, o1-mini, o3-mini, GPT-4 Turbo, GPT-3.5
  * Anthropic: Claude 3.7 Sonnet, Claude 3.5 Sonnet, Claude 3.5 Haiku, Claude 3 Opus
  * Google: Gemini 1.5 Pro, 1.5 Flash, 2.0 Flash, 2.5 Flash, 2.5 Pro
  * DeepSeek: DeepSeek-V3, DeepSeek-R1, DeepSeek-Chat, DeepSeek-Reasoner
  * Meta / Open Source: Llama 3.3 70B, Llama 3.1 70B/8B, Mixtral 8x7B, Qwen 2.5 72B
  * Dynamic pricing overrides via `register_model_pricing()`.
  * Computes prompt cost, completion cost, and aggregated trace cost in USD.

--------------------------------------------------------------------------------
F. Pluggable Dual-Tier Storage Layer
--------------------------------------------------------------------------------
1. SQLite Storage Engine (Default / Local Development):
   * Write-Ahead Logging (`PRAGMA journal_mode=WAL`) enabled for high-concurrency
     non-blocking reads and writes.
   * Connection isolation with thread-local pooling.
   * In-memory LRU cache (128 items) and 3-second cached statistics aggregation.
   * Multi-column indexes on status, start_time, duration_ms, and project.

2. Cloud SQL / MySQL Engine (Production Distributed):
   * Full SQLAlchemy integration with connection pooling.
   * `pool_pre_ping=True` to eliminate stale/dropped connection socket errors.
   * Automatic connection recycling (`pool_recycle=1800`) tailored for
     Google Cloud SQL 30-minute proxy timeouts.

--------------------------------------------------------------------------------
G. Zero-Dependency Standalone Windows Binary (.exe)
--------------------------------------------------------------------------------
Problem:
Non-technical team members, QA testers, and operations teams frequently require
access to the observability UI without configuring Python virtual environments.

Solution:
Configured automated PyInstaller bundling via `build_exe.py`:
  * Embeds FastAPI, Uvicorn, SQLAlchemy dialects, and the single-page HTML UI
    into a self-contained ~49MB Windows binary (`langgraph-observe.exe`).
  * Features an interactive console prompt to configure or override the database URL.
  * Automatically detects OS display environment and opens the default web
    browser directly to `http://127.0.0.1:8765/`.
  * Incorporates crash-proof exit hooks so console logs remain visible on error.

--------------------------------------------------------------------------------
A. Instrumenting a FastAPI Application (Client SDK)
--------------------------------------------------------------------------------
from fastapi import FastAPI
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph_observe import instrument_fastapi, observe_graph

app = FastAPI(title="AI Agent Service")

# 1. Attach observability middleware
instrument_fastapi(
    app,
    server_url="http://localhost:8765",
    environment="production",
    project="customer-agent",
    mask_pii=True
)

# 2. Define LangGraph workflow
class AgentState(TypedDict):
    query: str
    response: str

builder = StateGraph(AgentState)
def process(state: AgentState) -> dict:
    return {"response": f"Processed: {state['query']}"}

builder.add_node("process", process)
builder.add_edge(START, "process")
builder.add_edge("process", END)

# 3. Wrap compiled graph
agent_graph = observe_graph(builder.compile(), name="AgentWorkflow")

@app.post("/chat")
async def chat(data: dict):
    return await agent_graph.ainvoke({"query": data["query"], "response": ""})
